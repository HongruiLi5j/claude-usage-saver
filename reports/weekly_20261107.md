读法：**第一次请求上下文**是套件要盯的数（系统提示 + 工具 + skill 列表 + 首条 prompt），它涨了才说明套件让 prompt 变长；每 agent 请求数、平均上下文、输出涨，多半是任务本身变重。"all·all" 是主会话 + 子 agent 合计（agent 数 = 主会话文件数 + 子 agent 数），子 agent 单独涨而合计降，往往只是重活从主会话搬到了子 agent。三项分项之外还有少量未缓存 input，所以分项之和略小于合计。

读法：**每次请求成本**最能说明省额度措施本身的效果（不受你这周用得多还是少影响）；每天成本还取决于工作量。
两种单位：**本模型单位** = 每个模型按自己的输入价归一（同一模型内可比，跨模型不能比，和旧报告数字连续）；**Sonnet 5.5 当量** = API 美元 ÷ $2/M，Opus 5.5 的同样 token 记 2 倍（F1 采用的额度折算，未被额度数据精确证实，R 的 95% 区间 1.43–3.56）。价格来自 tools/pricing.py（官方定价页 11-06）：5.5 代缓存读是 0.05× 输入价，旧模型 0.1×。不等于订阅额度百分比。已排除基准/测试会话。
**样本提醒**：最近窗口不足 3 个完整天时，变化百分比没有意义，只看趋势。
