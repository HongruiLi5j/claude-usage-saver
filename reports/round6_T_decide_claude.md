# 第 6 轮 T 遗留的 3 个决定：主会话 Claude 的独立方案（先写下，再与 Codex 对照）

所有者规则：质量优先，会降质量的不采用，"持平"可接受；11-21 换 Pro。

## 数据（主会话 00:50 实测，只数元数据不看正文）
- Claude Code 2.1.319：单次工具输出 >30000 字节落盘，模型只看到开头 2KB（T 实测）。
- transcript 里落盘 94 次，全部来自 Bash，平均 104KB、中位 39KB。之后的动作：49 次没有再调用工具（直接答复或回合结束），5 次 Read 读落盘文件，37 次再跑 Bash（其中 26 次带 tail/head/grep/sed 过滤，19 次与原命令开头相同）。
- 也就是说，约 25% 的落盘后面跟了一次补救调用；其余 75% 的情况，开头 2KB 已经够用，或者模型没去看结尾。

## Q1 摘要预算（SUM_BYTES=16000；行数 120+4×失败数，上限 300）
**建议：保持 16000 字节，T2 去掉 PASSED 进度行之后再看行数上限要不要收。**
- 硬约束是 30000 字节（超过就只剩 2KB），16000 留了将近一半余量给中文（UTF-8 每字 3 字节）和 hook 的提示行。
- 往小调省的有限：测试输出每天只出现几十次，25 个失败时也就多约 5KB ≈ 1.3k token，相对每次请求几十 k 的上下文可以忽略；往小调的风险是失败名被截断（这正是 R28 修的质量问题）。按"质量优先"，不调。

## Q2 adapters/common/usaver_run.py（Codex/Gemini 用）换新摘要
**建议：换，但改成直接调用 `test_filter.summarize`，单一实现，不复制代码。**
- 同样的丢失败名 bug，修法 ~5 行，它已经 import test_filter。
- 风险低：adapters 还没上 PATH（H(1)–(6) 待所有者定），换了也不影响现在的使用；但要让 H 的 36 个离线测试和 Codex 真机解析重跑。
- 文件归 H，由 H 改（SendMessage H），按配对制让 Codex 复核。

## Q3 其它大输出落盘只给 2KB 预览，要不要做通用"保留开头+结尾"的 hook
**建议：不做。在 model-router / handoff 规则里加一句"预计输出很长的命令自己加 `| tail -n 80` 或 `grep`"即可，甚至可以不加。**
- 收益小：只有约 25%（约 24 次/2 周）跟了一次补救调用，每次补救是一次热缓存上的小请求，按 Sonnet 当量大约几 k token，占总用量远低于 0.1%。
- 风险大：通用 hook 要改写任意 Bash 命令（管道、退出码、交互、二进制输出），这正是 test_filter 花了 6 轮才修稳的那类问题；动到任意命令，改坏一次的代价远超省下的 token。
- 落盘本身对额度是好事：模型只看 2KB，而不是把 104KB 塞进上下文、之后每轮重复计费。
